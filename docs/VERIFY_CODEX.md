# 人工核对 Codex 额度

这一步核对的是订阅额度，和卡片底部的 token 数、API 等价金额不是一回事。

1. 在终端输入 `codex`，进入已经登录的 Codex。之后的 `/status` 要输入到 **Codex 对话框**，不是普通终端提示符。
2. 发一句“只回复 OK”，等它完成，让本机写入一份新的用量记录。
3. 暂停其他 Codex 任务（包括桌面 App、VS Code 和其他终端），在这次会话输入 `/status`。
4. 展开桌面挂件，切到 Codex。等约 15–30 秒，确认更新时间接近“刚刚”。
5. 对比同一套餐／额度池的 5 小时和 7 天窗口，分别看百分比和重置时间。

**注意已用和剩余的方向。** 挂件显示已用；如果 Codex 写的是 `80% left`，挂件应显示约 `20%`。

| Codex 显示（举例） | 挂件应该显示 |
|---|---|
| 5h：80% left | 5 小时：20% 已用 |
| Weekly：65% left | 7 天：35% 已用 |
| 今天 18:00 重置；当前 16:30 | 约 1 小时 30 分钟后重置 |

两边的显示取整可能造成约 1 个百分点的差异；倒计时随时间走，可能差一两分钟。
若差距明显，先确认没有其他任务继续消耗额度，再等下一次刷新。`context` 是对话上下文容量，不要拿它跟订阅额度环比较。

如果 `/status` 没有套餐额度字段，或显示尚未加载，这次对照应记为“无法对照”，不能算通过。
若一直不一致，保留同一分钟拍摄的两个画面及挂件更新时间；分享前遮住邮箱、账号、目录和会话内容。
